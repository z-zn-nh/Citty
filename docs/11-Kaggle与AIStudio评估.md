# Kaggle vs 飞桨 AI Studio：哪个适合我们

> 2026-10-06。**本文里的平台额度/会话规则我没法联网核实**（本机实测海外线路超时，firecrawl 也没装），
> 标 ⚠️ 的一律"以官网为准"；标 ✅ 的是**本机实测或在代码里验证过**的。
> 相关：[08-远端服务器部署方案](08-远端服务器部署方案.md)、[09-VPS规格汇总](09-VPS规格汇总.md)、[10-免费方案与最小部署](10-免费方案与最小部署.md)。

---

## 0. 结论

> **做实验/批量处理：Kaggle。**
> **国内网络不折腾：AI Studio。**
> **做实时服务：两个都不行**——它们没有公网入站端口、单次会话最长 12h、每周/每天有额度上限。

更重要的是：**现在这个阶段你两个都不需要用**。
引擎已经能在本机 + 免费云 API 上跑通（见 [10](10-免费方案与最小部署.md)），
Kaggle/AI Studio 的正确定位是**"免费实验台"**——用来做那些"必须在自己音频上跑才作数"的事。

---

## 1. 判断标准（为什么不能只看"免费几小时"）

我们的引擎每切一句话就要调一次推理服务，所以我们真正需要的是：

| 需求 | 权重 | 说明 |
|---|---|---|
| 进程能长期存活 | 高 | 看 2 小时视频，服务不能中途死 |
| 能从我这边连进去 | 高 | 需要**入站**地址（我们的远端方案靠 SSH 隧道） |
| 显存够放下我们的组合 | 高 | 最重的组合约 13~20GB（[09](09-VPS规格汇总.md) 实测体积推导） |
| 能装依赖、能下模型 | 中 | `pip install funasr faster-whisper`；HF 下权重 |
| GPU 代际别太老 | 中 | T4/V100 **都不支持 bf16**，见 §3 |
| 额度够用 | 中 | 30h/周 ≈ 4.3h/天，日常看视频够，长时间压测不够 |

**笔记本平台在"进程存活 + 入站地址"这两条上天然不合格**——它们的设计目标是交互式实验，不是常驻服务。

## 2. 逐项对比

| 维度 | Kaggle（Google） | 飞桨 AI Studio（百度） |
|---|---|---|
| GPU | T4×2 或 P100（二选一） | V100 等，**按"算力卡"结算** |
| 单卡显存 | 16GB / 卡 → **T4×2 合计 32GB** | 16GB |
| 架构代际 | T4 = Turing **sm_75**：有 fp16 张量核，**无 bf16、无 fp8** | V100 = Volta **sm_70**：fp16 可用，**无 bf16、无 flash-attn2** |
| 额度 | ⚠️ 30h/周 GPU（+20h TPU），每周重置 | ⚠️ 每日免费时长，**但按算力卡结算（要签到/做任务攒）** |
| 单次会话 | ⚠️ 最长 12h；20 分钟无交互断连 | ⚠️ 通常 8~12h（以官网为准） |
| 出网 | ⚠️ 手机验证后可开，`pip` / HF 都能下 | ⚠️ 免费档出网限制较多（可能要走 ModelScope） |
| **入站端口** | **没有** | **没有** |
| 持久磁盘 | ⚠️ `/kaggle/working` 20GB，`Save Version` 后可当 Dataset 复用 | ⚠️ 有项目空间，规则以官网为准 |
| 国内可达性 | ⚠️ **本机实测海外线路超时**（github.com 都不通）→ 你可能需要换个网络环境 | ✅ **不用梯子，最顺** |
| 门槛 | 手机验证解锁 GPU/联网 | 百度账号，部分算力要实名 |
| 生态 | 标准 CUDA + pip，跟我们的代码零摩擦 | 百度系（PaddlePaddle / ModelScope）为主，pip 也能用 |

### 对我们的用途打分

| 用途 | Kaggle | AI Studio |
|---|---|---|
| 跑一次本地 ASR 选型 A/B（1~2 小时任务） | ✅✅ 很合适 | ✅ 合适 |
| 批量配音（demucs + TTS，几小时） | ✅✅ 12h 会话够 | ⚠️ 算力卡可能不够连续 |
| 多服务同时托管（ASR+MT+TTS 分卡） | ✅✅ **32GB 是它的独家优势** | ❌ 单卡 16GB |
| 下 HF 权重 | ✅ 出网开了就行 | ⚠️ 待核实 |
| 你在国内连得上 | ⚠️ 实测本机超时 | ✅✅ 最顺 |
| 当实时字幕/配音服务 | ❌ | ❌ |

## 3. 和我们模型清单的适配（关键：T4/V100 都没有 bf16）

| 我们的模型 | T4（16GB） | V100（16GB） | 备注 |
|---|---|---|---|
| SenseVoice-Small | ✅ fp16/fp32 | ✅ | 234M，随便跑 |
| faster-whisper large-v3-turbo | ✅ fp16 / int8 | ✅ | 最省心的组合 |
| Hy-MT2-1.8B / 7B（GGUF） | ✅ llama.cpp `-ngl` 全上卡 | ✅ | Q4_K_M/Q6_K 都行 |
| Qwen3-ASR-1.7B | ⚠️ 用 vLLM 要**显式 `dtype=float16`** | ⚠️ 同上 | 默认 bf16 会失败 |
| CosyVoice2-0.5B / IndexTTS-2.5 | ✅ fp16/fp32 | ✅ | 显存见下 |
| demucs | ✅ | ✅ | 1GB 量级 |
| P100（另一选项） | — | 建议**别选**：sm_60 太老，很多新 kernel 没有 | 选 T4 |

**显存对账**（体积来自 [09](09-VPS规格汇总.md)，按"参数量×精度 + 激活/框架开销"推导）：

| 组合 | 显存 | 能否塞进单张 T4（16GB） |
|---|---|---|
| SenseVoice + Hy-MT2-1.8B | ≈ 3.3 GB | ✅ 轻松 |
| Qwen3-ASR-1.7B + Hy-MT2-7B | ≈ 10.0 GB | ✅ 可以 |
| 上面 + CosyVoice2 + demucs | ≈ 14.0 GB | ✅ 贴着上限（建议分卡） |

> **T4×2 的真正价值不是"算得快"，而是"32GB 总量可以分卡托管"**：
> ASR 挂 `cuda:0`、MT 挂 `cuda:1`、TTS 挂 `cuda:0`——**不需要张量并行**，就是进程级别的设备分配。
> 这刚好覆盖我们"最重的三个同时常驻≈20GB"的需求（[09](09-VPS规格汇总.md) §2），
> 等于**白拿一台比 24GB 单卡更大的机器**，代价是每周只有 30 小时。

## 4. 为什么不能当实时服务（诚实说明）

| 硬伤 | 后果 |
|---|---|
| 没有公网入站端口 | 只能靠反向隧道（cloudflared/ngrok/frp）绕；而且**平台条款通常不允许把笔记本当常驻服务/代理**，属于灰色用法、有封号风险 |
| 单次会话 12h 上限 | 长时间看视频会中途断 |
| 20 分钟无交互断连 | 你不点它，它就掉线 |
| 30h/周（Kaggle）| 相当于**每天只能看 4.3 小时**；AI Studio 的算力卡机制也类似 |
| 不能保证随时开机 | 想"打开就看"的体验做不出来 |

**结论**：把它们当"推理网关"是想错了。要做实时，路只有两条（[08](08-远端服务器部署方案.md) / [09](09-VPS规格汇总.md) 已经写过）：
**本机引擎 + 免费云 API（0 元，现在就能用）**，或**按量租 GPU（¥2/h 量级，用完关机）**。

## 5. 怎么用才最值（三个具体用途，第一个已经给你写好了）

### 用途 1（最值）：本地 ASR 选型的 A/B —— 脚本已就绪

云端 A/B 只能测"平台提供的模型"，但"到底该选 SenseVoice / Whisper-turbo / Fun-ASR-Nano"
**必须用你自己视频的音频、在本地模型上测**。已经写好单文件脚本：

```
deploy/kaggle/asr_ab_local.py
```

用法（Kaggle / AI Studio 的 Notebook 里，两格搞定）：

```python
!pip install -q funasr modelscope faster-whisper
!python asr_ab_local.py --wav /kaggle/input/MY_WAVS/sample.wav --ref /kaggle/input/MY_WAVS/ref.txt
```

输出：每个模型的**加载耗时、最佳/中位延迟、RTF、CER（中文按字）/ WER（英文按词）**，
并写一份 JSON 到 `/kaggle/working/asr_ab.json`。指标口径与 `citty ab` **完全一致**（中文按字、英文按词、Levenshtein）。

- ✅ **本机已用 `--dry-run` 验证流程与指标计算**（英文 WER、中文 CER 都算对了；顺手修掉一个 BOM 相关的坑，见 §7）
- ⚠️ 真实模型那一段（funasr / faster-whisper 加载）**没在本机跑过**——本机 torch 是 CPU 版、也没装 funasr，需要你在免费 GPU 上首跑确认

### 用途 2：P2 配音批处理（正好匹配 12h 会话形态）
`demucs` 分离人声 → CosyVoice2 合成 → 混流 → 下载。20GB 输出足够装音频。**离线批处理，慢一点无所谓**。

### 用途 3：P3 路由的小分类器微调
T4×2 上做 LoRA 微调小模型没问题（7B 以内）。用不着 JEV-9B 那 17GB。

### 省时间的关键技巧（务必用）
第一次会话把模型下好 → **Save Version**，让 20GB 模型缓存留在 Output →
**下次作为 Dataset 挂载**，免重复下载。否则每次会话都要重下 1.6~10GB。

另外：Kaggle/AI Studio 里**没有 systemd**，我们 [deploy/server](deploy/server) 里那两个服务改成
`nohup python asr_openai_server.py ... &` 后台起即可（`asr_openai_server.py` 和 `llama-server` 都能直接复用）。

## 6. 最终建议

| 你想做什么 | 用哪个 |
|---|---|
| **现在就想看视频有字幕** | **都不需要**：本机引擎 + 免费云 API，只差一个 ASR 免费额度 |
| 用自己音频做 ASR 选型 A/B、批量配音、微调小模型 | **Kaggle**（先确认你能连上 kaggle.com；本机实测海外线路超时） |
| 国内网络不折腾、要中文生态 | **AI Studio**（先确认免费档能否出网下模型，不能就走 ModelScope） |
| 实时字幕 / 实时接管原声 | **本机** 或 **按量 GPU**，别用笔记本平台 |

**一句话**：Kaggle 是更强的那台免费机器（T4×2 = 32GB、生态标准），**做实验选它**；
AI Studio 赢在"国内不用梯子"，**当备用**；**实时服务谁都别指望**。

## 7. 本轮顺手修掉的一个真 bug（值得记一笔）

`deploy/kaggle/asr_ab_local.py` 的 `--dry-run` 自检时发现：**参考文本带 BOM 会把 CER/WER 算错**。

- PowerShell 的 `Set-Content -Encoding UTF8` / 记事本另存为，都会在文件头写 UTF-8 BOM（`\ufeff`）。
- 按 `utf-8` 读进来，BOM 会变成一个**隐形字符**混进参考文本 →
  中文 CER 从 `1/13 = 0.077` 变成 `2/14 = 0.143`，**指标凭空翻倍，而你看不出原因**。
- 已修：`citty/bench.py` 和 `deploy/kaggle/asr_ab_local.py` 都改用 `encoding="utf-8-sig"` 读参考文本。
- 这是"用真实数据跑一遍"才能暴露的问题——和 [05](05-引擎使用说明.md) 里记的那 3 个 bug 同一类。
