# 本地部署可行性：这台电脑撑不撑得住

> 体检日期 2026-10-06。**本文只做调研，没有下载任何模型**——所有体积数字来自 HuggingFace 元数据接口
> （仓库文件真实大小），不是估算。磁盘可用空间与体检前一致，可自行核对。
> 配套结论见 [06-ASR选型](06-ASR选型.md)、引擎现状见 [05-引擎使用说明](05-引擎使用说明.md)。

---

## 0. 结论：够，但必须"分档 + 不常驻"

| | 能不能 | 说明 |
|---|---|---|
| 只做 ASR + 翻译（本地） | ✅ **完全够，且很轻松** | 下载 **~1.8GB**，显存占用可做到 **≈0**（ASR 走 CPU） |
| 再加配音（TTS） | ✅ 够，但要算账 | +4.5GB 下载，显存要腾出 2~3GB；**不能和 1.7B 的 ASR 同时常驻** |
| 全都要 + 大模型 + 路由模型 | ⚠️ 不要这么干 | JEV-9B 一个就要 17.2GB；IndexTTS-2.5 要 6GB 显存，会把 8GB 卡塞满 |
| 4 个组件同时常驻显存 | ❌ | 8GB 物理上限摆在那里，只能"按需加载/切换" |

**一句话**：你的机器跑「本地 ASR + 本地翻译」绰绰有余（甚至可能比现在的云端更快），
但"本地配音"需要排队使用显存，而不是和别的模型一起常驻。

## 3. 显存账本：8GB 到底怎么分（按 7.2GB 可用算）

| 方案 | ASR | MT | TTS | 显存合计 | 可行性 |
|---|---|---|---|---|---|
| **A · 省显存（推荐起步）** | SenseVoice GGUF q8 **CPU，0 GB** | Hy-MT2-1.8B Q6_K，1.6GB | CosyVoice2，2.2GB | **3.8 GB** | ✅ 还能再塞个 0.6B ASR 做对比 |
| **B · 质量优先** | Qwen3-ASR-1.7B，4.5GB | Hy-MT2-1.8B Q4，1.3GB | 不能常驻（排队） | 5.8 GB | ✅ 字幕质量最好；配音时需先卸载 ASR |
| **C · 流式优先** | qwen3-asr-0.6b-streaming，1.2GB | Hy-MT2-1.8B Q4，1.3GB | CosyVoice2，2.2GB | 4.7 GB | ✅ 感知延迟最低（英文流式） |

**内存账本**：llama.cpp 用 mmap 加载 GGUF，权重不进 RAM 常驻（按页调入），
所以本地 ASR+MT 的**内存增量大约 1~3GB**，你有 11GB 可用 → 够。
但 32GB 里已经被吃掉 20GB，**跑本地推理时别开着大型游戏/一堆 Chrome 标签**。

## 4. 延迟会变好还是变差？（诚实分析）

现在云端实测：**ASR 含上传 ≈0.9s + 翻译 0.8~2.1s**（翻译慢在大模型生成 + 公网 RTT）。

本地预估：
| 环节 | 预估 | 依据 |
|---|---|---|
| SenseVoice CPU | 10s 音频 **0.3~0.6s** | 官方 70ms/10s（GPU）；16 核 CPU 打 3~5 折仍远超实时 |
| Hy-MT2-1.8B Q6_K（4060） | 一条字幕（~40 token）**0.3~0.8s** | 1.8B Q6 在 4060 上大约 60~120 tok/s |
| CosyVoice2 生成 4s 配音 | 0.5~1.5s | 官方 RTF 数据 |

**结论：本地可能比现在的云端更快**——因为省掉了音频上传（15s 音频上传就 2.1MB）和公网往返，
而且小模型（1.8B）生成一条字幕比云端 35B 快得多。**但这必须实测**，别拿估算当结论。

## 5. 五个真正的坑

1. **⚠️ C 盘只剩 18.9GB，而 HuggingFace/ModelScope 默认缓存写 C 盘。**
   下载前必须把缓存指到 E 盘（`HF_HOME=E:\hf`、`MODELSCOPE_CACHE=E:\ms`），否则一不留神就把系统盘塞满。
2. **⚠️ 当前的 PyTorch 是 CPU 版**（`2.12.0+cpu`），`torch.cuda.is_available()` 为 False。
   走 GPU 要么装 CUDA 版 torch（`pip install torch --index-url .../cu126`，下载 ~3GB），
   要么绕开 torch 直接用 **llama.cpp**（二进制几十 MB）——这是我最推荐的路子。
3. **8GB 显存不能"全都要"**：见第 3 节的三个方案，同一时刻只放必要的两三个模型。
4. **许可差异**：SenseVoice 是 FunASR 自定义许可、IndexTTS-2.5 是 bilibili 自定义许可，
   CosyVoice2 / Hy-MT2 / Qwen3-ASR / Whisper 是 Apache 或 MIT。商用前逐条核对。
5. **首次下载 + 环境搭建时间**：`llama.cpp` 若用预编译二进制是秒级；若要自己编译 CUDA 版约 10 分钟。

## 6. 建议的执行顺序（每步都能回退，随时可以停）

| 步骤 | 动作 | 新增磁盘 | 收益 | 风险 |
|---|---|---|---|---|
| **1** | llama.cpp + **SenseVoice GGUF q8**，ASR 走 CPU | **0.29 GB** | ASR 完全本地，**零显存** | 极低 |
| **2** | + **Hy-MT2-1.8B Q6_K**（llama.cpp / Ollama） | +1.37 GB | 翻译本地化，省掉免费 API 依赖 | 低 |
| 3 | 与云端做 A/B（`citty ab` 已经支持配置化切换） | 0 | 用数据决定是否弃用云端 | 无 |
| 4 | 想要更高质量：+ `Qwen3-ASR-0.6B` 或 `1.7B` | +1.75~4.38 GB | 中文/口音质量上限 | 显存要排队 |
| 5 | P2 配音：+ **CosyVoice2-0.5B** | +4.52 GB | 离线配音/音色克隆 | 需 torch + ~2.2GB 显存 |
| ✗ | 不要：JEV-9B / Index-Translate-35B / IndexTTS-2.5 + 1.7B ASR 同时常驻 | — | — | 显存爆炸 |

**前两步总共只有 ~1.7GB 磁盘、几乎不占显存**——这是"先本地化 ASR+MT，配音暂缓"的最优解。

## 7. 云端 vs 本地 该怎么选（最终建议）

| 场景 | 用哪个 |
|---|---|
| 迭代开发、多语种试错、临时评测 | **云端**（改一行配置就换模型，零磁盘） |
| 正式看视频、离线、不想消耗额度、隐私敏感内容 | **本地**（ASR CPU + MT GPU，延迟更低且完全免费） |
| 配音（P2） | 先云端验效果（CosyVoice2/MOSS-TTSD 硅基流动上有），确认要做再本地化 |
| 路由（P3） | 规则 + 小模型足够；**不要碰 JEV-9B** |

两条路在架构上是同一套代码：`asr.backend` / `mt.backend` 都是适配器，
**本地和云端只是不同的 adapter 实例**——所以现在先跑云端、以后再本地化，不用重写任何东西。
