### 3.3 真实数据暴露并修掉的 3 个 bug（值得记一笔）

只有拿**真音频**跑才会暴露，单元测试里都是绿的：

1. **24-bit WAV 直接崩**：`buffer size must be a multiple of element size`——原来只处理 8/16/32-bit，
   而手机/录像/录音笔导出的 wav 大量是 24-bit。已新增 `decode_pcm()` 统一支持 8/16/24/32-bit（含符号扩展）。
2. **`file` 模式不按真实时间播放**：文件被瞬间循环几千次，音频时钟直接跑到 **41714 秒**，45 秒的测试刷出 **397 段**、
   丢帧 10940，还瞬间打光了一次 ASR 配额。已给 `FileSource` 加真实时间节流（`audio.file_realtime: true`）。
3. **ASR 失败会疯狂重试**：欠费/断网时每个切句都打一次请求。已加**熔断**：连续失败 3 次 → 暂停 5s，
   错误事件只在第 1、5、10… 次上报（一个 22 秒的欠费测试从几百条错误降到 4 条）。

### 3.4 ⭐ 一个和预期不同的重要发现：修正 pass 不是只会变好
"…before we ship this thing."
- 第一遍（无上下文）：`在发布这款产品之前，我们先来看看基准测试结果。` ✅ 更贴切
- 修正后（带上下文）：`在发货前，我们来看看基准测试结果。` ❌ 反而更差

说明"给上下文"和"翻译更好"之间不是单调关系。**修正 pass 必须做 A/B**，不能默认它一定提升质量：
```yaml
mt:
  corrector:
    enabled: true    # 想关掉就设 false
```
后续要做的实验：修正 pass 用「同一模型带上下文」vs「同一模型不带上下文」vs「更大模型（免费 35B API）」三组对比，用实际视频评测。

## 4. ASR：已经接的是哪家、怎么换、没额度怎么办

**当前配置**（`config.yaml`）已经是真实的云端 ASR，不再是 mock：

```yaml
asr:
  backend: openai_compat
  openai_compat:
    api_style: transcriptions
    base_url: https://api.siliconflow.cn/v1
    api_key_env: SILICONFLOW_API_KEY
    model: Qwen/Qwen3-ASR-1.7B     # 实测 RTF 0.173；同平台上另有 SenseVoiceSmall(0.161) / XingChenASR(0.304)
```

换模型/换厂商只需改这三个字段（`base_url` / `model` / `api_key_env`），代码不用动：

| 提供方 | base_url | 可用的 ASR 模型 | 说明 |
|---|---|---|---|
| **硅基流动**（已实测可用） | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall`、`Qwen/Qwen3-ASR-1.7B`、`XingChenAGI/XingChenASR-V3.2(-Ultra)`、`XingChenASR-Diarize-V3.0`（带说话人） | 国内直连；**需实名认证领取免费额度**，否则 402 |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3-asr-flash`、`qwen-audio-3.0-asr-flash`、`fun-asr-flash-2026-06-15`，另有 `*-realtime*` 实时系列 | 要先把 `api_style` 改成 `chat_audio`；**需在控制台开通模型服务**，否则 403 `AccessDenied.Unpurchased` |
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` | 英文最快最便宜，国内需代理 |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` / `gpt-4o-mini-transcribe` | 需代理 |

```powershell
Copy-Item D:\Citty\.env.example D:\Citty\.env
notepad D:\Citty\.env                       # 填 SILICONFLOW_API_KEY=sk-...
python D:\Citty\tools\probe_asr_key.py --list   # 一条命令验证：key / 鉴权 / 调用形态 / 真跑一句官方样例
```

> 接口是 OpenAI 兼容的 `POST /audio/transcriptions`（multipart 上传一段 wav，16k 单声道最稳）。
> 不兼容的厂商就加一个 adapter（照抄 `citty/asr.py` 里的 `OpenAICompatASR`）。
> **没有额度时怎么办**：用 `tools/mock_asr_server.py` 起一个本地假 ASR，把 `base_url` 指过去，
> 就能在完全不花钱的情况下验证「适配器 → 翻译 → 字幕」这几段（见第 2 节最后一条命令）。

## 5. 字幕与前端

三种模式（运行时切换，前端立即生效）：
```powershell
curl -X POST http://127.0.0.1:8756/api/mode -H "Content-Type: application/json" -d '{\"mode\":\"tgt\"}'
# mode: src(仅原文) | tgt(仅译文) | bilingual(双语，默认)
```
桌面字幕窗里 **右键** 就有菜单（双语 / 仅译文 / 仅原文 / 重连 / 退出），**左键拖拽**移动位置。

导出 SRT（双语，译文在上原文在下）：
```
浏览器打开 http://127.0.0.1:8756/api/srt    # 直接下载 citty.srt
```

术语表（强约束，视频里专名多的时候最有用）：
```powershell
curl -X POST http://127.0.0.1:8756/api/glossary -H "Content-Type: application/json" `
  -d '{"carbon fiber":"碳纤维","crack resistance":"抗裂性","Index-Translate":"Index-Translate"}'
```
或写进 `config.yaml` 的 `mt.glossary`，重启即生效。

## 6. WebSocket 协议（给前端/扩展开发者）

`ws://127.0.0.1:8756/ws`，JSON 文本帧。

服务 → 前端：
```jsonc
{"type":"session","mode":"bilingual","src_lang":"auto","tgt_lang":"zh-Hans","asr":"mock","mt":"bilibili_free"}
{"type":"segment","id":"seg-0014","rev":1,"t_start":54.5,"t_end":58.8,
 "src":"Honestly, nobody expected...","tgt":"说实话，没人料到...",
 "stability":"final","latency_ms":{"asr":260.7,"mt":1095.2,"total":1355.9}}
{"type":"error","code":"MT_FAILED","msg":"..."}
```
前端 → 服务：`{"type":"set_mode","mode":"tgt"}`

`stability` 三态就是"实时字幕"的机制：
- `partial`：VAD 刚切出一段，还没识别（前端可以先占位）
- `stable`：ASR 出了原文，正在翻译（先显示原文）
- `final`：译文到了；之后可能再来一条 **同 id、rev+1** 的修正版本

前端只按 `id` 就地更新、`rev` 递增判断是否重绘，就不会闪烁。

## 7. 排障

| 现象 | 原因 / 解决 |
|---|---|
| **ASR 报 402** `account balance is insufficient` | 硅基流动余额/免费额度为 0。去 <https://cloud.siliconflow.cn> 完成**实名认证**领额度（新用户赠送），或充 ¥10 就够跑很久 |
| **ASR 报 403** `AccessDenied.Unpurchased` | 百炼侧：模型服务没开通 / 没实名 / 用的是业务空间(ws)的 key。去控制台「模型广场」点开通，或换主账号的 API-KEY |
| 翻译报 **412** | 哔哩哔哩免费 API 要求浏览器 User-Agent。代码里已内置；自己写请求要带上 UA |
| 没字幕 / 一直等待 | `audio.source` 是不是 `file`/`mock`？真看视频要改成 `loopback`；确认系统真的在出声 |
| 切句太碎 | `vad.silence_commit_ms` 从 350 调到 500~800 |
| 一整段吞掉 | `vad.max_segment_ms` 调小（默认 8000），或 `energy_threshold_db` 调到 -35 抗噪 |
| 一个测试瞬间刷出几百段 | 音频源没按真实时间播。已修（`audio.file_realtime: true`）；自建音频源时注意节流 |
| 音频文件读不了 | 之前只支持 8/16/32-bit PCM，24-bit 会崩。已修（`decode_pcm` 支持 8/16/24/32） |
| 延迟高 | ASR（含上传）≈0.9s + 翻译 0.8~2.1s。想更快：切句阈值调小、用流式 ASR、或换更快的云端 MT |
| 桌面字幕窗不出现 | 程序会 `-topmost` 置顶；若在锁屏/全屏独占游戏里可能看不到，先用浏览器版 `/overlay` |
| 引擎起不来 | 端口被占：`.\run.ps1 doctor` 会提示，改 `config.yaml` 的 `server.port` |
| 想清空日志/产物 | `out/` 目录可以随时删 |

## 8. 下一步（按优先级）

1. **给硅基流动账户领取免费额度 / 充点钱**（当前 402），然后把 `audio.source` 换成 `loopback`，
   **用真实视频跑 30 分钟**：记录切句质量、延迟 P50/P95、错译类型、术语表收益。
2. **用 `tools/probe_asr_key.py` + `citty ab` 定主档**：现在候选里有 SenseVoice / Qwen3-ASR-1.7B / XingChenASR 三家，
   用你自己视频的 3 类样本（英文科技 / 中文口播 / 带 BGM）跑一遍。
3. **修正式的 A/B**（见第 3.4 节的发现）：上下文版 / 无上下文版 / 更大模型版三组对比。
4. **加真实流式 ASR**：现在是"整句切完再送 ASR"，延迟 = 句长 + 识别时间。
   百炼的 `qwen3-asr-flash-realtime` 可以直接把感知延迟降下来（不需要本地部署）。
5. **P2 配音可以继续走云端**：硅基流动上已经有 `FunAudioLLM/CosyVoice2-0.5B` 和 `fnlp/MOSS-TTSD-v0.5`，
   **不需要下载 IndexTTS-2.5**（那一步才会真正占几个 GB 磁盘）。
