# 16 · P3-a 路由埋点（只采集、不改行为）

> 目标：攒出**真实分布**，让 P3-b 的"分领域换翻译模型"有数据支撑，而不是拍脑袋。
> 这一阶段**不改变任何翻译行为** —— 用哪个模型和领域判断完全无关。
> 代码：`apps/engine/citty/router.py`（判断）+ `routing_log.py`（落盘与报表）。

## 一、为什么先攒数据再改行为

路由的收益必须用数据证明。在**没有评测集、没有真实分布**之前就按领域切换模型，
等于用随机数替换掉一个"至少不会更差"的默认模型。所以顺序是：

1. **P3-a（本阶段）**：只判断、只记录，跑两周；
2. 拿到"哪类视频最多、哪类错得最多、哪类被修正得最频繁"；
3. **P3-b**：只对**有数据支撑**的领域换模型，其余一律用默认。

## 二、怎么判断领域（heuristic）

零模型、零显存、纯 CPU 字符串匹配，实测**单次判断 0.1ms 量级**。

打分规则（全部可解释，没有黑箱）：

| 规则 | 分值 |
|---|---|
| 正文命中一个 **ASCII 单词**（词边界匹配，避免 "ai" 命中 "said"） | 1.0 |
| 正文命中一个**多词短语** | ×1.8 |
| 正文命中一个**中文词**（按子串匹配，中文没空格） | 1.0 |
| 命中出现在**标题/UP主/分区**里（元数据） | ×3.0 |

置信度 = `0.75 × 证据强度 + 0.25 × 与第二名的差距`，其中证据强度 = `min(1, 得分 / 4)`。
于是：

| 命中情况 | 置信度 | 是否认领域（阈值 0.50） |
|---|---|---|
| 单个词 | **0.44** | ❌ 记成 `default` |
| 两个词 | 0.62 | ✅ |
| 三个词 | 0.81 | ✅ |
| 一个多词短语 | 0.59 | ✅ |

**为什么阈值卡在 0.50**：单词级匹配有同形异义问题，实测就撞到过 ——
`"…try to be patient"` 里的 `patient` 命中医学词表，单独一个词就把整段判成"医学"。
所以设定"**至少两个词命中才认领域，单命中一律记 `default`**"，宁缺勿滥。
（证据仍然照记 —— `domain_scores` 里存着原始打分，事后能从 `default` 里把它捞回来重标。）

**元数据的价值（实测对比）**：同一段音频（官方英文样例）两次运行：

| 条件 | 第 1 段的判定 | 置信度 |
|---|---|---|
| 只喂正文 | `default`（正文只有 `listening` 一个命中） | 0.438 |
| 喂了标题「保母级英文听力训练｜朋友闲聊口语」 | **`language`** | **0.875** |

结论很直白：**元数据（标题/UP主/分区）比正文值钱**，能拿到就一定要传。

## 四、落盘格式

一次会话一个文件：`out/routing/<session_id>.jsonl`（**该目录在 .gitignore 里，不进 git**）。

- **第 1 行是表头**：记下这次会话用的 ASR/MT 后端、语言对、修正开关、术语表大小、元数据。
  没有表头的话，过两周拿到一堆日志根本不知道是哪个模型产的。
- **之后每段多行**：同一段会因修正 pass 出现多行（`phase` 区分 `mt` / `correction`），
  `rev` 递增 —— 这正是"这句话被重译过几次"的数据来源。

字段（对齐路线图要求，`✅` 是要求里点名的）：

```json
{"session_id": "20261009-080733", "seq": 2, "at": "2026-10-09T08:07:33",
 "idx": 1, "rev": 1, "phase": "mt", "t_start": 0.4, "t_end": 2.35, "dur_s": 1.95,
 "src_lang": "auto", "tgt_lang": "zh-Hans",
 "domain_guess": "language", "domain_stable": "language",
 "domain_confidence": 0.875, "domain_evidence": "meta:口语, meta:听力, meta:英语",
 "domain_scores": {"language": 4.8}, "router_ms": 0.113,
 "asr_text": "Oh, yeah, yeah.", "mt_text": "哦，是啊，是啊。",
 "model_used": "Index-Translate-35B-A3B", "latency": {"asr": 500.0, "mt": 643.8, "total": 1143.8},
 "stability": "final", "stats": {"segments": 1, "translated": 1, "dropped": 0, "errors": 0}}
```

对应关系：`domain_guess` ✅、`asr_text` ✅、`mt_text` ✅、`model_used` ✅、`latency` ✅、`revisions`(=`rev`) ✅。

**每写一行就 flush**：引擎在长测里是被 `process.kill()` 硬杀的，缓冲区里的数据等于没有。

实测输出（3 个会话 / 24 个分段，真实数据）：

```
领域分布（所有会话合计）
    language      15   62.5%  █████████████████████████
    default        9   37.5%  ███████████████

领域 × 质量（P3-b 要拿这个决定分模型）
    领域            分段     被修正句     修正率      平均总延迟      字数
    language      15        8   53.3%       920ms     650
    default        9        3   33.3%       721ms     365

延迟   ASR p50 132.4ms / p95 854.3ms    MT p50 501.5ms / p95 598.6ms    端到端 p50 645.1ms / p95 1335.3ms
埋点自身开销 p50 0.1ms / p95 0.2ms / 最大 0.386ms（n=24）← 用来证明「埋点没引入可感知延迟」
rev 分布 {1: 13, 2: 11}（rev>1 = 被修正 pass 重译过的句子数）
```

最后两行是**验收证据**：

- **埋点开销 p95 = 0.2ms**，相对端到端 645ms 可以忽略 → 满足"埋点不引入可感知延迟"；
- **领域 × 修正率**就是 P3-b 的决策依据：某个领域修正率明显偏高，才值得为它单独换模型/术语表。

## 八、本阶段的边界（诚实清单）

- **不做**：不换模型、不改 prompt、不改术语表、不影响字幕（`domain` 只作为字段透传给前端）；
- **迟滞只用于记录**：连续 2 次同一猜测才改判 `domain_stable`，但即使改判了也不影响翻译 ——
  这个机制是**给 P3-b 预留**的（避免模型来回切换），本阶段只是把它跑起来观察切换频率；
- **关键词匹配固有局限**：同形异义（`patient`）、梗和反讽、混合领域（科技+财经）都会不准。
  这正是要攒数据的原因 —— 两周后的真实分布会告诉我们这套启发式够不够，不够再上 JEV 决策模型。
- **元数据依赖调用方**：B 站/YouTube 的标题与分区需要上层传进来，本阶段不抓网页。
