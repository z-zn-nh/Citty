# 分阶段路线图 · 验收标准 · 风险与合规

> 单人全职口径；每个阶段都有"能停下来的点"，避免战线拉长。

---

## 0. 总览

| 阶段 | 目标 | MVP 工期 | 稳定版 | 关键交付物 | 可停下吗 |
|---|---|---|---|---|---|
| **P1** | 实时字幕（中↔英 + 双语） | 2~3 周 | +2~3 周 | 桌面字幕窗 + 本地引擎 + SRT 导出 | ✅ 停下也是完整产品 |
| **P3-a** | 路由埋点（只采集、不改行为） | 3~5 天 | — | 域标签 + 延迟/修订埋点 + 数据落盘 | ✅ |
| **P2-a** | 离线配音（整片） | 2~3 周 | +2 周 | ASR+MT+TTS 管线 + 对齐/混音 + AI 标识 | ✅ 停下也是完整功能 |
| **P4** | 多语种（目标 10 语种） | 3~4 周 | +2~4 周 | 语种矩阵 + 排版 + 每语种评测 | ✅ 语种可增量交付 |
| **P3-b** | 路由生效（分模型翻译） | 1~2 周 | +1~2 周（评测） | routing_table.json + 迟滞切换 | ✅ 效果不好就保持单模型 |
| **P2-b** | 实时配音（实验） | 3~5 周 | 视质量 | 缓冲策略 + 延迟对齐 + TTS 预热 | ⚠️ 允许砍掉 |

**推荐顺序（已按用户决定调整）**：P1 → P3-a → **P4（先只做字幕）** → P3-b → P2-a → P2-b。

> **2026 顺序调整记录**：把 P2（配音替换）整体推到后面，理由与代价如下。
>
> 依赖核查（谁依赖谁）：
> - P3-a 埋点只依赖 P1 的 segment 流水线，**与 TTS 完全无关**；
> - P4 的字幕部分（ASR 语种覆盖 + MT 语种覆盖 + 排版）**不依赖 TTS**，只有"能否配音"那一列会先空着；
> - P3-b 依赖 P3-a 的数据 + **至少两个真实可选的 MT 模型**，同样不依赖 TTS；
> - 所以顺序调整**没有任何阻塞依赖**。
>
> 代价（诚实记录）：
> 1. P4 的语种矩阵少"能否配音"一列，将来做配音时要按语种回头补验证（每语种 10 条回归用例）；
> 2. **P2-a 的处理时长（≤1.5× 视频时长）依赖当时的 MT 选型** —— 先做完 P4/P3-b 后 MT 可能已换成本地模型，
>    这个指标要**重新标定**，不能沿用旧数；
> 3. 近期少一个"能导出文件直接给人看"的成品（P2-a 是唯一有可分享产物的阶段）。
>
> **新增前置项（原路线图未显式列）**：做 P3-b / P4 之前需要**第二个真实 MT 模型**（现在只有
> `bilibili_free` 一个真实后端，单模型无从路由；且 10 语种的互译覆盖度免费接口未验证）。
> 候选：Index-Translate-2B Q4 1.22GB / Hy-MT2-1.8B 1.37GB / NLLB-200-distilled-600M 2.29GB。
> 预估 1~2 天，属前置步骤而非独立阶段。
>
> TTS 选型由用户自行决定，**只冻结接口不冻结模型**：任何 TTS 满足"文本+音色+语速进→音频出、
> 能报告真实时长、支持语速控制、失败抛异常"四条即可接入 `TTSBackend` 适配器。

## 1. P1：实时字幕（中↔英，双语）

### 里程碑
| # | 里程碑 | 验收标准 |
|---|---|---|
| M1 | 捕获链路 | WASAPI loopback 连续抓 30 分钟不断流；暂停/恢复播放不崩 |
| M2 | 字幕上屏 | 任意播放器播英文视频，出现中文字幕；三种模式（原文/译文/双语）可切换 |
| M3 | 延迟达标 | 说话→上屏端到端 **≤1.5s（本地 MT）**，P95 ≤2.5s；10 分钟无累积漂移 |
| M4 | 修正 pass | 整句结束后 3s 内字幕被更准确的版本覆盖，且不闪烁、不重复 |
| M5 | 播放器交互 | seek / 暂停 / 倍速 / 切换视频 后，字幕时间轴正确重建，无"影子字幕" |
| M6 | 导出与配置 | 导出 SRT（原文/译文/双语三种）；术语表可导入（CSV/JSON）；模型后端可切换 |
| M7 | 稳定性 | 连续 2 小时运行，内存无泄漏（±10% 内），OOM 自动降档不崩 |

### 语言方向
- **en→zh**：流式 ASR(en) + MT(→zh) —— 主路径，也是 B 站/YouTube 生肉的主要诉求。
- **zh→en**：流式 ASR(zh) + MT(→en)；中文 ASR 建议试 FunASR/SenseVoice 与 nemotron 对比。
- **双语**：不是额外翻译，而是渲染层的显示模式（原文与译文都留着）。

### 技术选（对应 `02`）
ASR：`WhisperLiveKit` 框架 + 先 faster-whisper 跑通，后换 `nemotron-3.5-asr-streaming-0.6b`（chunk 320ms）；
MT：本地 `Index-Translate-2B`（FP8/GGUF），兜底用官方免费 35B API 或 `Hy-MT2-1.8B`。

### 失败退路
若实时延迟压不到 2.5s：把 ASR 降级到 160ms chunk + 只上屏"稳定前缀"，牺牲准确率保延迟；再不行就退回"半实时"（3~5s 延迟、质量更好），并在 UI 上明示。

## 2. P3-a / P3-b：JEV 路由

### P3-a（埋点，3~5 天）
- 实现 `RouterBackend` 接口，先只有 `heuristic.py`（比如：按关键词/标题/UP 主分区猜领域）；
- 每个 segment 落盘：`{session_id, domain_guess, asr_text, mt_text, model_used, latency, revisions}`；
- **不做任何行为改变**。跑两周，积累真实分布（哪类视频最多、哪类错得最多）。

### P3-b（生效）
- 接入 `autotrust/JEV-9B` 的 `/v1/decide`（`kind=choice`，8~16 个领域选项，选项名后各带一行"什么时候用"）；
- 触发频率：每 30~60s 一次 + 话题切换时触发（可由 MT 模型顺便做话题切换判断，零成本）；
- 置信度门控：`p ≥ 0.6` 且连续 2 次一致才切换（**迟滞**），切换时保留时间轴；
- 输出 `routing_table.json`：`domain → (mt_model, glossary_id, prompt_template, style)`；
- 评测：按 `02` 第 5 节的 A/B 方案，产出"分领域最优模型"结论；**没有数据支撑的领域一律用默认模型**。

### 验收标准
- 路由带来的**平均 COMET/人工分提升 ≥ 1 分（5 分制）且无领域显著下降**，否则回滚到单模型；
- 切换开销 ≤ 1s（不含模型换入），且字幕无跳变；
- 路由本身延迟 P95 ≤ 400ms（含 JEV 调用）。

### 显存策略（前提约束）
JEV-9B bf16 ≈ 18GB，8GB 卡只能：① Q4 GGUF 按需加载（与 ASR 挤显存，需实测）；② 云端；③ 先不上 JEV，用 2B 级 + prompt 分类。**三种都接受，按机器档位自动选。**

## 3. P2-a / P2-b：TTS 接管原声

### P2-a 离线配音（2~3 周）
流程直接抄 `bilibili/Index-Translate` 的 `video-dub`（Apache-2.0）：

```
mp4 → ffmpeg 抽 16k 单声道 → demucs 人声分离 → Silero-VAD 切句(≤9.5s, 带时间戳)
    → 逐句 MT(+术语表) → TTS(IndexTTS-2.5 音色克隆) → 时间轴对齐(双向变速/音节控制)
    → 混音(伴奏回填) → 封装(copy 视频流) + 导出配音字幕 SRT
```

验收：
- 单集 20 分钟视频，端到端处理时间 ≤ 视频时长的 1.5×（用 8GB 卡 + 2B MT，可能更慢，需实测）；
- 配音与画面**不同步偏差 ≤ 300ms**（按句统计，P95）；
- 保留 BGM/音效（人声分离回填），主观听感无"机器人腔"（IndexTTS-2.5 音色克隆效果）；
- **输出文件包含 AI 生成标识**（元数据 + 可选画面角标）。

### P2-b 实时配音（实验，3~5 周）
- 缓冲 **3~8s**，边播边配；播放器侧用延迟/倍速对齐；
- 原声处理：实时只做 **ducking（原声 -12dB）**，人声分离留给离线；
- 显存：TTS 独占（~6GB），**MT 必须切云端 API**；TTS 提前预热，禁止会话内冷启动；
- 验收：连续 10 分钟不爆音、不漂移；用户可一键切回原声；失败自动降级为"只出字幕"。

**明确不承诺**：零延迟同声传译、多人对话的说话人一致音色、音乐类内容的原声替换。

## 4. P4：多语种

### 扩展路径
1. **矩阵先画全**：源语种（ASR 支持）× 目标语种（MT 支持）× 是否可配音（TTS 支持）× 排版类型（LTR/RTL/CJK/泰文）。
2. **优先语种**（按需求）：ja、ko、es、fr、de、ru、pt、it、ar（RTL）、th（无空格）。
3. **每语种交付清单**：ASR 可用性验证 + MT 质量抽测（100 句）+ 字幕排版适配 + 字体 fallback + 术语表模板 + 回归用例入集。
4. **瓶颈预判**：
   - TTS：IndexTTS-2.5 只有 5 语种 → 其他语种要么引入多语 TTS（CosyVoice3/F5-TTS/云端），要么该语种**只做字幕不做配音**；
   - 排版：阿拉伯/希伯来要处理双向混排（数字/拉丁嵌入）、泰文无空格断行、CJK 禁则处理；
   - 评测：低资源语种没有参照译文，需要人工或回译（back-translation）做粗筛。

验收：每个语种有 **10 条固定回归用例**（3 条长句、3 条含专名/数字、2 条口语、2 条梗/网络语），换模型或改 prompt 后必须全跑。

## 5. 风险登记表（含触发条件与响应）

| # | 风险 | 触发条件（怎么知道发生了） | 响应 | 责任阶段 |
|---|---|---|---|---|
| 1 | 显存不足 OOM | 加载模型时报 OOM / 系统卡顿 | ModelPool 自动降档（9B→2B，TTS 延后加载）；UI 提示 | 全阶段 |
| 2 | 端到端延迟超标 | P95 > 2.5s | 减小 chunk、只上屏稳定前缀、MT 换更小模型/多线程优化 | P1 |
| 3 | 修正 pass 闪烁 | 字幕频繁重排/跳动 | 只在 `final` 后修订；同一 id 覆盖而非新增；差分渲染 | P1 |
| 4 | 时间轴漂移 | 长视频字幕逐渐落后 | 用音频时钟而非墙钟；定期用 VAD 边界重同步 | P1 |
| 5 | 中文 ASR 质量差 | 中文视频错字率高 | 换 FunASR/SenseVoice；加热词表；后处理正则 | P1/P4 |
| 6 | 配音不同步 | 偏差 > 300ms | 音节控制（Index-Homura）+ 变速对齐限幅；超限句重译缩短 | P2 |
| 7 | TTS 冷启动卡顿 | 会话开始 2~5s 无配音 | 预热；开始时先播原声再切配音 | P2-b |
| 8 | 免费 API 抖动/限流 | 429/超时 | 本地兜底后端；请求重试 + 降级到 2B；会话内不断流 | P1 |
| 9 | 模型下架/改名 | 拉取失败 | 权重本地化（models/ 目录），pin 版本号 | 全阶段 |
| 10 | 路由抖动 | 领域标签频繁翻转 | 迟滞 + 最小切换间隔（≥60s）+ 置信度门控 | P3-b |
| 11 | 路由无收益 | A/B 显示提升不显著 | 保留单模型 + 只启用术语表（零风险收益） | P3-b |
| 12 | 多说话人/重叠 | 字幕串人、翻译错代 | 开说话人分离（VibeVoice/Sortformer）；同说话人分别维护上下文 | P1/P4 |
| 13 | DRM 无法捕获 | 捕获到静音 | UI 明确提示不支持，不尝试绕过 | P1 |
| 14 | 版权/平台条款 | 抓流 + 导出配音视频外传 | 默认本地显示、不落盘；导出功能声明个人使用责任 | 全阶段 |
| 15 | AI 配音合规 | 未标识的合成语音对外发布 | 强制标识 + 音色授权确认 + 不内置真人声音模板 | P2 |

## 6. 合规清单（发版前必须过一遍）

**法律/监管**
- [ ] AI 合成语音/视频：输出显著标识（《互联网信息服务深度合成管理规定》对生成或显著改变语音的要求）。
- [ ] 声音权：音色克隆需获得本人同意（《民法典》第 1023 条参照肖像权）；产品内提供授权确认与说明书。
- [ ] 不提供真人（明星/公众人物）声音模板库；不引导克隆他人声音。
- [ ] 抓取平台内容：仅本地个人观看用途；下载/再分发配音视频的条款风险由用户承担，产品页面写明。

**许可证**
- [ ] 逐模型核对：Index-Translate/Index-Echo（Apache-2.0 ✅）、Hy-MT2（Apache-2.0 ✅）、JEV（Apache-2.0 ✅）、Whisper/WhisperLiveKit（MIT/Apache ✅）、Nemotron（OpenMDW-1.1 ⚠️ 逐条看）、VibeVoice（MIT ✅）、**IndexTTS-2.5（bilibili 自定义许可 ⚠️ 商用务必核对）**、TranslateGemma（Gemma 条款 ⚠️）。
- [ ] 分发产品时附第三方许可清单（NOTICE 文件）。

**隐私**
- [ ] 默认全本地；任何云端调用（含官方免费 API）必须显式开关 + 提示"音频/文本将上传"。
- [ ] 不上传、不缓存用户音视频；日志脱敏；术语表本地存储。
