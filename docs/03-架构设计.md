# 架构设计（P1 定型版）

> 目标：一套本地引擎 + 多前端，P1 只做实时字幕；P2/P3/P4 通过 adapter 增量接入，不重写。
> 硬件基线：Windows + RTX 4060 Laptop 8GB + 32GB RAM。

---

## 1. 产品形态：三选一，推荐 B 为主 + A 为辅

| 形态 | 捕获方式 | 覆盖场景 | 优点 | 缺点 |
|---|---|---|---|---|
| A. 浏览器扩展（MV3） | `chrome.tabCapture` | B 站/YouTube 网页 | 无需装驱动、无虚拟声卡、和播放器同页面好做 overlay | 抓不到本地播放器/桌面客户端；扩展不能跑 Python 推理（需本地服务） |
| **B. 桌面悬浮字幕 + 系统音频捕获（推荐）** | **WASAPI loopback** | **任何播放器/客户端/网页/直播** | 通用性强；字幕窗可置顶穿透 | 需要本地服务进程；Windows 优先 |
| C. OBS/播放器插件 | OBS 音频源 / mpv IPC | 推流、本地播放 | 与场景原生集成 | 面向人群窄 |

**推荐落地**：核心是**本地引擎服务（Python）**，B 作为主前端（透明置顶字幕窗），A 作为轻量入口（复用同一个引擎服务，WebSocket 连本地）。两者共用协议，不重复实现。

---

## 2. 总体架构

```
┌──────────────── 前端层（可多开） ────────────────┐
│  桌面字幕窗（透明置顶/穿透/拖拽）  │  浏览器扩展 overlay  │  OBS 文本源  │
└───────────────────▲─────────────────────────────┘
                    │ WebSocket（字幕事件）/ HTTP（控制、术语表、导出）
┌───────────────────┴─────────────────────────────┐
│              引擎服务（Python, uv）               │
│  ┌─────────┐  ┌──────────┐  ┌──────────┐        │
│  │ 音频源   │→│ 会话管理  │→│ 管线编排  │        │
│  │ Capture │  │ Session  │  │ Pipeline │        │
│  └─────────┘  └──────────┘  └────┬─────┘        │
│   WASAPI loopback / 扩展推流      │              │
│  ┌───────────────┬────────────────┼────────────┐ │
│  │ VAD/Segmenter │  ASR Adapter   │ MT Adapter │ │
│  │ Silero / 静音 │ nemotron/whisper│ Index/Hy   │ │
│  └───────────────┴────────────────┴────────────┘ │
│  ┌──────────────┬──────────────┬────────────────┐ │
│  │ 术语表/TM 缓存│ 修正 Pass    │ Router(P3)     │ │
│  └──────────────┴──────────────┴────────────────┘ │
│  ┌──────────────┬──────────────┬────────────────┐ │
│  │ TTS Adapter  │ 对齐/混音     │ 导出 SRT/ASS    │ │
│  │ (P2)         │ (P2)         │                │ │
│  └──────────────┴──────────────┴────────────────┘ │
└──────────────────────────────────────────────────┘
```

**关键设计原则**
1. **引擎与前端分离**：引擎是常驻 Python 服务；前端可以是任意语言/进程，靠协议通信。这样 Windows 桌面窗、扩展、OBS 都能复用。
2. **一切皆 Adapter**：`ASRBackend` / `MTBackend` / `TTSBackend` / `RouterBackend` 四个协议接口，配置切换实现，不写死模型。
3. **字幕是"可修订对象"**：每条 segment 有稳定 id，允许被修正 pass 覆盖（前端按 id 就地更新，而不是追加）。
4. **时间轴是唯一真相**：所有产出（字幕、配音、导出）都挂在同一个 `Segment` 时间轴上。

## 3. 统一数据结构与协议

### 3.1 核心结构

```python
@dataclass
class Segment:
    id: str                 # 稳定 id（前端按此更新）
    t_start: float          # 相对视频/流的秒
    t_end: float
    src_text: str
    tgt_text: str
    src_lang: str           # BCP-47：zh-Hans / en / ja ...
    tgt_lang: str
    speaker: str | None     # diarization 结果
    stability: str          # "partial" | "stable" | "final"
    revision: int           # 递增；前端用它判断是否需要重绘
    domain: str | None      # P3 路由打标
    model_used: str | None
    latency_ms: dict        # {"asr":.., "mt":.., "total":..} 用于观测
```

`stability` 三态是**实时字幕的核心机制**：
- `partial`：流式 ASR 的临时结果，直接上屏（可能变），前端灰字显示；
- `stable`：LocalAgreement/AlignAtt 判定不再变的前缀 → 定稿上屏；
- `final`：整句结束（VAD 静音或句末标点）→ 触发**修正 pass**，用上下文重译，覆盖同一 id。

### 3.2 前端协议（WebSocket，JSON Lines）

```jsonc
// 服务 → 前端
{"type":"session","session_id":"S1","src_lang":"en","tgt_lang":"zh-Hans","mode":"bilingual"}
{"type":"segment","id":"seg-0042","rev":1,"t_start":12.4,"t_end":15.1,
 "src":"So the new chip runs at 3.2 gigahertz.","tgt":"所以这颗新芯片运行在 3.2 GHz。",
 "stability":"partial","latency_ms":{"asr":410,"mt":120,"total":640}}
{"type":"segment","id":"seg-0042","rev":2,"tgt":"这颗新芯片的主频是 3.2 GHz。","stability":"final"}
{"type":"status","asr":{"backend":"nemotron-0.6b","chunk_ms":320},"mt":{"backend":"index-2b","vram_mb":2300}}
{"type":"error","code":"AUDIO_DEVICE_LOST","msg":"..."}

// 前端 → 服务
{"type":"set_mode","mode":"tgt_only"}          // src | tgt | bilingual
{"type":"set_langs","src":"auto","tgt":"zh-Hans"}
{"type":"glossary","upsert":{"carbon fiber":"碳纤维","crack resistance":"抗裂性"}}
{"type":"seek","t":123.4}                       // 播放器 seek：清空未决字幕
{"type":"pause"} / {"type":"resume"}
{"type":"export","format":"srt","path":"D:/out/ep01.zh.srt"}
```

**为什么用 WS + JSON**：本地回环开销可忽略；浏览器扩展和桌面窗都能直接消费；调试用 `websocat` 就能看全链路。

### 3.3 字幕三种模式（"支持字幕"的具体定义）

| 模式 | 显示 | 用途 |
|---|---|---|
| `src` | 仅原文 | 听力练习/校对 |
| `tgt` | 仅译文 | 追剧默认 |
| `bilingual` | 双语（默认译文在上、原文在下，可切） | 学外语/核对 |

渲染细节（容易被低估、但决定观感）：
- 字体/字号/描边/阴影/背景不透明度可调；行宽限制（英文 ~42 字符/行，中文 ~20 字/行）；
- **最多两行**，超长自动按语义断行（按标点/连词，不硬切词）；
- 位置可拖拽，支持"避让底部 UI"的边距；
- 点击穿透（游戏/全屏时）；
- 多显示器、DPI 缩放（Per-Monitor DPI）适配；
- 长句持续时间与阅读速度（CPS/CPL）检查，过快时延长展示或缩写。

## 4. 显存账本（8GB 硬预算）

| 档位 | 常驻组件 | 显存估计 | 用途 |
|---|---|---|---|
| **Lite（默认）** | ASR 0.6B + MT 1.8B/2B(FP8/INT8) | 1.3 + 2.3 + 0.7 ≈ **4.3GB** | 日常实时字幕 |
| **Lite+VAD/分离** | 上面 + Silero(CPU) | 不变（跑 CPU） | 推荐做法：VAD 走 CPU |
| **Dub（P2 离线）** | ASR + MT(CPU/API) + **TTS 0.8B** | ~6GB(TTS 独占) | 离线配音；MT 切云端或 CPU-GGUF |
| **Quality（离线/云端）** | MT 9B / 35B API / S2ST 22GB | 超本地 | 导出高质量字幕、整片配音 |

**三条硬规则**：
1. **VAD、人声分离、正则后处理一律放 CPU**（i7-12850HX 24 线程够用），把显存留给 ASR/MT/TTS。
2. **模型换入换出要显式做**：`ModelPool` 管理"热模型"集合，切换时先释放再加载（2~5s），UI 显示"切换中"，并禁止在实时会话中做无预热换入。
3. **云端后端是显存不足时的第一逃逸路径**，且必须支持"临时降级"（同一会话内切后端不丢时间轴）。

## 5. 延迟预算与优化手段

| 环节 | 预算 | 优化手段 |
|---|---|---|
| 捕获 | 20~50ms | WASAPI 小缓冲；独立回调线程不做任何重活 |
| VAD+分块 | 320~560ms | chunk 320ms 起步；静音 ≥300ms 立即 commit 整句 |
| ASR | 30~100ms 计算 | 0.6B 流式；fp16；只跑当前 chunk |
| 稳定策略 | 0~400ms | 用"稳定前缀"抢先上屏，别等整句 |
| MT | 80~250ms（本地 2B） | 首 token 优先流式返回；batch=1；KV cache 复用系统提示前缀 |
| 渲染 | 16~50ms | 事件驱动重绘；避免整窗重排 |
| **合计** | **≈0.7~1.5s** | 云端 MT 则 ~1.0~2.2s |

**修正 pass（强烈建议 P1 就做）**：句子 `final` 后 1~3s 内，用"前 3~5 句 + 术语表 + 领域 prompt"重译并覆盖。用户几乎无感（字幕本来就是读完就过），但能显著修掉专名、代词、跨句指代问题。为此：
- MT 请求要带 `<context>` 槽（Index-Echo/Index-NativeLong 有对应设计，文本模型直接拼进 prompt）；
- 缓存句级译文，避免重复请求；对同一 segment 的多次修订只保留最后一版；
- 修正失败不回滚（保证"有字幕"优先于"字幕完美"）。

**缓存与去重**
- **术语表（glossary）**：全局 + 领域两级；命中术语时用硬约束格式（Index-Translate 的 `-g/-H`），实测最有效。
- **TM（翻译记忆）**：相同/近似句子直接复用（视频重播、片头片尾、系列剧高频）。用规范化文本 hash + 相似度阈值。
- **静音/音乐段跳过**：VAD 判定非语音直接不送 ASR/MT。

**播放器交互**
- `pause/resume/seek/倍速` 必须处理：seek 时**清空未决 segment**并重建时间基准；倍速播放不改变时间轴语义（只影响真实时间与音频时间映射）；
- 直播流：时间轴用"流内相对秒"，断流重连后重置 session 并提示。

## 7. PoC 骨架（第一周就能跑通的最小链路）

```python
# tools/poc/pipeline_poc.py —— 捕获 → VAD → ASR → MT → 打印字幕
# 依赖：pip install soundcard numpy faster-whisper openai httpx silero-vad
import queue, time, numpy as np, soundcard, httpx

SR = 16000
BLOCK = 320 * SR // 1000          # 320ms 块，对应 nemotron 的低延迟档

def capture(q):
    mic = soundcard.get_microphone(id=str(soundcard.default_speaker().name), include_loopback=True)
    # ↑ WASAPI loopback：拿到"扬声器在放什么"
    with mic.recorder(samplerate=SR, channels=1, blocksize=BLOCK) as rec:
        while True:
            q.put(rec.record(numframes=BLOCK).copy())

def asr(q, out):
    from faster_whisper import WhisperModel
    m = WhisperModel("large-v3-turbo", device="cuda", compute_type="int8_float16")
    buf = np.zeros(0, dtype=np.float32)
    while True:
        buf = np.concatenate([buf, q.get().reshape(-1)])
        if len(buf) < SR * 2:              # 简化版：攒 2s 出一次（正式版换成真流式）
            continue
        segs, _ = m.transcribe(buf, language=None, vad_filter=True, beam_size=1)
        text = "".join(s.text for s in segs).strip()
        buf = np.zeros(0, dtype=np.float32)
        if text:
            out.put(text)

def mt(inp, out, tgt="zh-Hans", base="http://127.0.0.1:8000/v1", model="Index-Translate-2B"):
    with httpx.Client(timeout=30) as c:
        while True:
            src = inp.get()
            r = c.post(f"{base}/chat/completions", json={
                "model": model,
                "messages": [{"role": "user", "content":
                    f"把下面的文本翻译成简体中文，只输出译文，不要解释。\n{src}"}],
                "temperature": 0, "max_tokens": 512}).json()
            out.put((src, r["choices"][0]["message"]["content"].strip()))

def render(inp):
    # 正式版：把 (src, tgt) 通过 WS 推给字幕窗/扩展；PoC 直接打终端
    while True:
        s, t = inp.get()
        print(f"\r\033[2m{s}\033[0m\n{t}\n", flush=True)

if __name__ == "__main__":
    ...
```

```powershell
# 或偷懒用官方的免费 35B API：base_url=https://index-translate.bilibili.com/v1
```

**PoC 验收线**：能连续 10 分钟为任意播放器里的英文视频输出中文字幕，连续运行不崩，端到端延迟（说话→上屏）**≤2.5s**。达到这条线，后面的工作就都是"优化"而不是"能不能做"。

## 8. 观测与调试（别省这部分）

第一版就要有的埋点，因为 P3 的路由决策全靠这些数据：

| 指标 | 采集点 | 用途 |
|---|---|---|
| 各环节耗时（asr/mt/render/total） | Segment.latency_ms | 定位延迟瓶颈 |
| 字幕修订次数（segment revisions） | 前端 | 衡量 ASR 稳定性 |
| 域标签 + 置信度 | Router | P3 路由表的输入 |
| 用户手改字幕 | UI（可选功能） | 高质量评测样本来源 |
| 术语命中率 | MT 层 | 评估术语表收益 |
| 显存占用 / OOM 事件 | ModelPool | 档位自动降级触发条件 |

**"用户手改字幕 → 进评测集"是这条产品最值钱的数据飞轮**：它天然给出"哪类视频 + 哪个模型 + 错在哪"的标注样本，直接喂给 P3 的路由表和 P4 的语种优化。
