> 2026-10-06。**本文所有数字都是在这台机器（i7-12850HX 16C/24T）上实测的**，不是估算。

## 1. 要装什么、要下什么（三条命令）

```powershell
# 1) 装运行时（28 MB，不是 torch 的 3 GB）
D:\Citty\.venv\Scripts\python.exe -m pip install sherpa-onnx

# 2) 下模型（228 MB，放 D:\Citty\models\sensevoice-onnx\）

curl.exe -L -o D:\Citty\models\sensevoice-onnx\tokens.txt       "$base/tokens.txt"

# 3) 跑（配置档已经写好了：config.local.yaml）
.\run.ps1 -Config D:\Citty\config.local.yaml doctor

```

实测下载速度：HF 直连 **0.9 MB/s**（228MB 用了 263 秒）。慢的话换 `https://hf-mirror.com/...` 同路径。

## 2. 实测数据（这台机器，CPU，int8，8 线程）

### 2.1 延迟随片段长度的变化（关键：**13.5 秒是悬崖**）

| 片段长度 | 最佳耗时 | RTF | 备注 |
|---|---|---|---|
| 3.0 s | **67 ms** | 0.022 | |
| 5.0 s | **115 ms** | 0.023 | 典型切句长度 |
| 8.0 s | **174 ms** | 0.022 | |
| 12.0 s | **247 ms** | 0.021 | 线性区间上限 |
| 12.8 s | 261 ms | 0.020 | |
| 13.0 s | 272 ms | 0.021 | 到这里都还是线性的 |
| **13.5 s** | **586 ms** | 0.043 | ⚠️ **开始变陡** |
| 14.0 s | **1246 ms** | 0.089 | ⚠️ **5 倍** |
| 15.05 s | 1421 ms | 0.094 | 整段英文样例 |

> **操作结论：切句长度保持 ≤ 12 秒**。现有默认 `segmenter.max_speech_ms: 12000` 正好卡在悬崖前，别调大。
> （12 秒以内，每多 1 秒音频只多约 20 ms 推理。）

### 2.2 线程数（每档独立进程测，避免热降频污染）

| num_threads | 5 秒片段耗时 | RTF |
|---|---|---|
| 4 | 123 ms | 0.025 |
| **8** | **110 ms** | **0.022** ← 最优 |
| 12 | 133 ms | 0.027 |

**8 线程是这个 CPU 的甜蜜点**（16C/24T 上再往上加反而变慢）。`config.local.yaml` 已设 8。

### 2.3 准确率（有真参考才算）

| 样例 | 参考来源 | 结果 |
|---|---|---|
| `official_zh.wav`（4.2s 中文） | **人工写的真参考** | 转写 **完全一致 → CER 0.0** |
| `official_en.wav`（15.05s 英文访谈） | 见 §4 的坑 | 转写连贯（"But he did very well when he started writing for other people."），但**没有可信参考文本，所以不报 WER** |

### 2.4 全链路（本地 ASR + 免费翻译）

```
.\run.ps1 -Config D:\Citty\config.local.yaml file out\samples\official_en.wav 18
```
```
✔   11.10-  15.00 rev1 [915ms]
   EN: But he did very well when he started writing for other people.
   ZH: 但他开始为他人创作时，表现非常出色。
统计: {"segments": 5, "translated": 5, "dropped": 0, "errors": 0}
```
**5 段 / 5 句翻译完成 / 0 丢弃 / 0 报错。** 单句端到端 ≈ **0.6~1.2 秒**（本地 ASR 0.1~0.25s + 免费翻译 0.5~0.9s）。

一次性开销：模型载入 **0.96 秒**（`warmup: true` 会在启动时做掉，不占第一句字幕）。

## 3. 配置档长什么样

`config.local.yaml` 关键几行：

```yaml
asr:
  backend: local_sherpa
  local:
    model: D:\Citty\models\sensevoice-onnx\model.int8.onnx
    tokens: D:\Citty\models\sensevoice-onnx\tokens.txt
    num_threads: 8
    provider: cpu          # 装了 CUDA 版 onnxruntime 可以改 cuda
    language: ""           # 空 = 自动（中/英/日/韩/粤）
    use_itn: true          # 数字与标点规范化
    warmup: true
mt:
  backend: bilibili_free   # 免费、无需 key
```

代码侧新增：`citty/asr.py` 里的 **`LocalSherpaASR`**（`from_sense_voice(...)`），
`asr.backend` 写 `local_sherpa` / `local` / `sherpa` / `sensevoice_local` 都能用；
`citty doctor` 会检查模型文件在不在、sherpa-onnx 装没装。

## 4. 这一轮踩到的三个坑（都已处理）

| 坑 | 现象 | 处理 |
|---|---|---|
| **① 代理环境变量把 httpx 弄崩** | `NO_PROXY` 里带 `[::1]` + `HTTP_PROXY=http://127.0.0.1:6544` → `httpx.Client()` **在构造阶段**就抛 `InvalidURL: Invalid port: ':1]'`，看着像"网络不通"，其实请求根本没发出去 | 新增 `citty/net.py` 的 `make_client()`：先按环境变量建，失败就退化成 `trust_env=False` 直连并打警告；`doctor` 会显式报告这一项 |
| **② `out/ref.txt` 是假参考** | 它是手写的占位句（"The neural network was trained on a large corpus of subtitles."），**不是这段音频的真值** → 用它算出的英文 WER 全无意义 | 已改名 `out/ref_placeholder_wrong.txt`；**别用它算指标**。（顺带说明：用机器自己的转写当参考去算 WER 是循环论证，也别这么干） |
| **③ 切句长度没有上限意识** | 13.5s 之后 CPU 推理成本跳 5 倍 | 见 §2.1，保持 ≤12s |

外加一条环境卫生：项目原本没有 `.gitignore`，已补上（挡住 `models/`、`.env`、`out/` 等）。

## 5. 本地 vs 云端（P1 到底该选哪个）

| | 本地（sherpa-onnx SenseVoice） | 云端（免费额度） |
|---|---|---|
| 首期下载 | **228 MB** | 0 |
| key | **不需要** | 需要（且要实名/开通） |
| 显存 | **0** | 0 |
| 单句延迟 | ASR **0.07~0.25s** | ASR 含上传 ≈0.9s（实测） |
| 上限 | 你的 CPU/内存 | 免费额度，会被限速 |
| 隐私 | 音频**不出本机** | 音频要上传 |
| 断网可用 | ✅（翻译那一步还是要网） | ❌ |
| 风险 | 偶尔的识别错误自己承担 | 额度会变、服务会限流 |

在"百炼拿不到额度"的前提下，**本地这条路的延迟还更低**（0.1s vs 0.9s），因为省掉了音频上传的往返。

## 6. 想升级时的路线（同样 CPU，同样零显存）

`sherpa-onnx` **不止支持 SenseVoice**，我实际在它的 API 里看到了这几个入口，都可以走 CPU：

| API | 对应模型 | 什么时候换 |
|---|---|---|
| `from_sense_voice` | 本次用的（228MB int8） | 默认，够用 |
| `from_whisper` | Whisper 系 ONNX | 英文/多语种更稳 |
| `from_qwen3_asr` | Qwen3-ASR | 中文/方言质量优先 |
| `from_funasr_nano` | Fun-ASR-Nano | 中文专精 |
| `from_paraformer` | Paraformer | 中文流式老牌 |

翻译侧要本地兜底时才需要额外下：`Hy-MT2-1.8B-Q6_K 1.37GB`（llama.cpp）。**现在不需要**。
