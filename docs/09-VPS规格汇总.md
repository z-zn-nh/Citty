# VPS 规格汇总：四阶段全部实现，需要多大的机器

> 汇总日期 2026-10-06。**模型体积全部来自 HuggingFace 元数据接口（仓库真实字节数，不是估算）**；
> 运行显存是按"参数量 × 精度 + 激活/KV + 框架开销"推导的**估算**（本机没有可用 CUDA 的 torch，无法实测）；
> GPU 租用价格**未能在本机联网核实**（github.com 实测超时），标注为量级参考。
> 相关文档：[07-本地部署可行性](07-本地部署可行性.md)、[08-远端服务器部署方案](08-远端服务器部署方案.md)。

## 0. 一句话答案

> **推荐：24GB 显存 + 16 vCPU + 64GB 内存 + 200GB SSD（Ubuntu 22.04 / CUDA 12.4），境内按量租用。**

这个规格能把 P1~P4 的**全部常规模型都跑起来**，并且"字幕 + 翻译 + 配音"最重的三个可以**同时常驻不排队**。
价格量级：24GB 卡按量 **¥1.5~3/小时**（国内平台）；用完就关机。

| 档位 | 配置 | 能跑什么 | 价格量级（**以官网为准**） |
|---|---|---|---|
| **A · 最小可用** | GPU 8~16GB / 4 vCPU / 8GB RAM / 30GB | 只有 P1 字幕（SenseVoice CPU + 1.8B 翻译） | ¥1~1.5/小时（T4 16GB 档） |
| **B · 推荐（日常用）** | **GPU 16GB** / 8 vCPU / 32GB RAM / 80GB | P1 字幕 + P2 配音（CosyVoice2），可来回切换 | ¥1.5~2.5/小时 |
| **C · 舒适（全功能）** | **GPU 24GB** / 16 vCPU / **64GB RAM** / 200GB | P1+P2+P3+P4，最重的三个模型**同时常驻**，JEV-9B 按视频加载 | ¥1.5~3/小时（4090/3090 24G） |
| D · 全都常驻不排队 | GPU 48GB / 16 vCPU / 128GB RAM | 连 JEV-9B（17.2GB）也常驻 | ¥4~8/小时，**多数情况下没必要** |

**结论：买 24GB 那一档。** 下面解释为什么不是 8、不是 16、也不是 48。

## 1. 全部组件的资源账本

"常规好用"= 各家生态成熟、中文/英文都撑得住、随时能换掉的那一档。

### P1 · 实时字幕（必装）

| 角色 | 模型 | 权重体积 | 常驻显存（估） | 备注 |
|---|---|---|---|---|
| VAD | fsmn-vad（FunASR） | ~1 MB | CPU | 切句 |
| **ASR（主）** | **SenseVoice-Small** | **0.88 GB**（.pt）/ **0.24 GB**（GGUF q8） | **0~1.6 GB** | GGUF 走 CPU 时**零显存** |
| ASR（备） | whisper-large-v3-turbo（CT2 int8） | 1.51 GB | 1.6 GB | 英文最稳 |
| ASR（加强） | Qwen3-ASR-1.7B | 4.38 GB | ~5.0 GB | 中文/方言最好 |
| 标点恢复（可选） | ct-punc 或 sonar-base | 0.3~2.08 GB | ~0.4~2.0 GB | 中文长句有用 |
| **翻译（主）** | **tencent/Hy-MT2-1.8B Q6_K** | **1.37 GB** | **1.7 GB** | 33 语种，性价比之王 |
| 翻译（加强） | tencent/Hy-MT2-7B Q4_K_M | 4.31 GB | ~5.0 GB | 质量更高 |
| 翻译（备） | Index-Translate-2B Q4_K_M | 1.22 GB | 1.5 GB | 150 语种 |

→ **P1 最小组合（SenseVoice CPU + Hy-MT2-1.8B）只要 1.7GB 显存、1.6GB 磁盘。**

### P2 · 配音（接管原声）

| 角色 | 模型 | 权重体积 | 常驻显存（估） | 备注 |
|---|---|---|---|---|
| 人声分离 | demucs htdemucs | 0.16 GB | ~1.0 GB | 分离人声与 BGM，替换原声的必需品 |
| **TTS（主）** | **CosyVoice2-0.5B** | **4.52 GB** | **~3.0 GB** | 音色克隆、5 语种 |
| TTS（高质量） | IndexTTS-2.5 | 5.11 GB | **~6.0 GB** | 效果最好，但吃显存 + 非 Apache 许可 |
| TTS（备） | MOSS-TTSD-v0.5 | 3.83 GB | ~4.0 GB | 对话式配音 |

→ **P2 最小组合（demucs + CosyVoice2）≈ 4.0GB 显存、4.7GB 磁盘。**

### P3 · 视频类型路由

| 角色 | 模型 | 权重体积 | 常驻显存（估） | 备注 |
|---|---|---|---|---|
| 路由（原方案） | JEV-9B | **17.18 GB** | ~18 GB | 决策模型，一次前向；**按视频加载即可，不必常驻** |
| 路由（轻量替代） | Jev-Style-Qwen3.5-2B-Decision Q4_K_M | 1.22 GB | 1.5 GB | 2B 决策模型，可以常驻 |

**关键洞察**：路由是**每个视频判一次**，不是每句话判一次。
所以 JEV-9B 完全可以"看视频前加载 → 分类 → 卸载"，**这 17GB 不需要常驻**——24GB 卡完全够。

### P4 · 多语种

| 角色 | 模型/方案 | 额外显存 |
|---|---|---|
| 翻译/字幕多语种 | **不需要新模型**：Hy-MT2（33 语）、Index-Translate（150 语）已覆盖 | 0 |
| 说话人分离（访谈类） | pyannote/speaker-diarization-3.1 | ~1.0 GB |
| 配音多语种 | 受 TTS 语种限制，CosyVoice2 = 5 语种；更多语种要换 TTS | — |

## 2. 四档配置对照

| | A 最小可用 | **B 推荐** | **C 舒适（建议买这个）** | D 全常驻 |
|---|---|---|---|---|
| GPU 显存 | 8~16 GB | 16 GB | **24 GB** | 48 GB |
| vCPU | 4 | 8 | **16** | 16 |
| 内存 | 8 GB | 32 GB | **64 GB** | 128 GB |
| 系统盘 | 30 GB | 80 GB | **200 GB** | 300 GB |
| 常驻组合 | SenseVoice(CPU)+1.8B | +CosyVoice2 | ASR-1.7B + MT-7B + TTS-**同时常驻** | +JEV-9B 常驻 |
| 峰值显存 | 1.7 GB | 7.3 GB | **17.4 GB + 框架/碎片 2~3 GB ≈ 20 GB** | ~40 GB |
| 磁盘（全量模型） | 1.6 GB | 6.9 GB | **48 GB → 含环境与产物 ~70~120 GB** | ~60 GB |
| 缺什么 | 配音、质量档 ASR、路由 | 高质量 TTS、7B 翻译要轮流用 | —— | 只是"懒得切换服务"的奢侈 |

**为什么 C 是 24GB 而不是 16GB**：最重的三个常规模型同时常驻是
`Qwen3-ASR-1.7B(5.0) + Hy-MT2-7B(5.0) + IndexTTS-2.5(6.0) = 16GB`，
再加上 demucs(1.0)、标点(0.4)、PyTorch 上下文与显存碎片(2~3GB) → **16GB 会在边界上反复 OOM，24GB 才有余量**。
（如果 TTS 用 CosyVoice2 而不是 IndexTTS-2.5，峰值降到 ~13GB，16GB 卡勉强够——这就是 B 档。）

**为什么不是 8GB**：你本机现在就是 8GB，这正是"全套放不下、必须分档"的根源。8GB 只能跑 A 档。

**为什么不是 48GB**：唯一能装下的额外东西是"JEV-9B 常驻"，而 JEV-9B 按视频加载**每次只多花几秒**，
为了省这几秒多付一倍租金不划算。除非你以后要做**实时**内容分类（每句话都判类型），才需要。

想要 PyTorch 版 SenseVoice 再加上 0.88GB（合计 2.5GB）。

## 4. 内存 / CPU / 带宽账本

| 资源 | 需求 | 依据 |
|---|---|---|
| **内存** | **≥ 显存 + 8GB**；推荐 **64GB** | PyTorch 加载权重时主机内存也会镜像一份；CosyVoice2 为 fp32 权重（2GB）；ffmpeg/demucs 吃缓存 |
| **vCPU** | ≥ 8，推荐 **16** | funasr 预处理、ffmpeg 转码、demucs 分离都能吃满多核；CPU 档 ASR 还需要核数撑 RTF |
| **带宽（上行）** | **0.26 Mbps** 就够 | 16k 单声道 = 32KB/秒，5 秒切句 = 160KB（[08](08-远端服务器部署方案.md) 有完整推导） |
| **带宽（下行）** | 5 Mbps 够 | 回家的是字幕（几百字节）或配音音频（Opus ~20KB/句） |
| **下载** | 首次 2.6~48GB | 建议分批 |
| **GPU 架构** | compute ≥ 8.6 建议（Ampere 及以后） | fp8/int8 量化、FlashAttention；T4(7.5) 只能跑 fp16，勉强可用但慢 |

## 5. 软件环境要求（照抄就能开机即用）

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04 / 24.04（[08](08-远端服务器部署方案.md) 的 `bootstrap.sh` 按这个写） |
| 驱动 | NVIDIA driver ≥ 550（用 cu126 的 wheel 时）；租用平台镜像通常已装好 |
| CUDA | 12.4 / 12.6 |
| Python | 3.11~3.12（funasr / cosyvoice2 兼容性最好） |
| ffmpeg | 必须（P2 配音要用） |
| 国内下载 | `HF_ENDPOINT=https://hf-mirror.com`，或走 ModelScope（`modelscope download`） |
| 选镜像技巧 | 平台的"PyTorch 2.x + CUDA 12.4"基础镜像，能把装机从 40 分钟压到 5 分钟 |
| 一个重要设置 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`——长时间反复加载/卸载 TTS 会显存碎片化 |
| 架构建议 | ASR / MT / TTS **各自独立成 systemd 服务**（`deploy/server/bootstrap.sh` 就是这么装的），避免同进程内互相挤显存 |

## 6. 六个买机注意点

1. **必须境内**（沪/京/穗）：实测海外线路在这条网络上**直接超时**（github.com），买海外机器等于买废铁。
2. **按量计费 + 用完关机**：全套常驻的服务器不在看视频的时候纯烧钱。
3. **别在磁盘上省钱**：200GB SSD 在云上很便宜，模型 + 缓存 + 产物能轻松吃掉 100GB。
4. **先小后大**：先下 P1 那 2.6GB 跑通，再决定要不要下 17GB 的 JEV-9B。
5. **不要为了省租金选 8GB**：那正是你现在卡住的配置；最低配建议从 **16GB** 起。
6. **端口不要裸奔**：所有服务只监听 `127.0.0.1`，本地走 SSH 隧道（见 [08](08-远端服务器部署方案.md) §4）——
   不暴露端口就不会被盗用 GPU，也不需要备案。

## 7. 最终"常规好用"清单（一台 24GB 机器上的推荐搭配）

| 阶段 | 选型 | 体积 | 显存 |
|---|---|---|---|
| P1 字幕 | **SenseVoice-Small**（中文强/可 CPU 零显存）+ **Hy-MT2-1.8B** | 1.6 GB | 1.7 GB |
| P1 加强 | Qwen3-ASR-1.7B（中文/方言）+ Hy-MT2-7B（更准） | 8.7 GB | 10 GB |
| P2 配音 | **demucs + CosyVoice2-0.5B** | 4.7 GB | 4.0 GB |
| P3 路由 | 2B 决策模型常驻（1.2GB），**JEV-9B 按视频加载** | 18.4 GB | 1.5 / 18（轮换） |
| P4 多语种 | 复用上面两个翻译模型；访谈类加 pyannote | 0.1 GB | 1.0 GB |

**默认（每日常驻）**：SenseVoice-GGUF + Hy-MT2-1.8B + CosyVoice2 ≈ **6.3GB 显存**，留 17GB 余量给加强档和峰值。
**要质量时**：把 ASR 换成 Qwen3-ASR-1.7B、MT 换成 Hy-MT2-7B → **≈13GB**，24GB 仍有余量 6.6GB。
