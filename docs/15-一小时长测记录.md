# 15 · 一小时长测记录（P1 稳定性验收）

> 目的：P1 的短测（几十秒）证明不了"能连续跑一小时"。本文记录一次**真实 B 站视频、62 分钟、
> 全本地 ASR + 免费翻译**的连续运行，以及它暴露出来的问题。
> 复现命令见文末，原始数据留在 `out/longrun.csv` / `out/longrun.srt`。

## 一、测什么、怎么测

| 项 | 内容 |
|---|---|
| 素材 | B 站 **BV1ppah66EaW**《保母级英文听力训练…B1英文》，时长 100.4 分钟、234 万播放 |
| 抓取 | `tools/fetch_audio.py` → 47.1MB 音频（28 秒下完，1.64MB/s）→ 截 **前 62 分钟** 转 16k 单声道 WAV（113.5MB） |
| 素材体检 | 整体 -22.7 dBFS、峰值 0.949、静音占 35.8%（视频给学习者留的跟读停顿）、抽查转写正常 |
| 链路 | loopback 采集（`扬声器 (网易虚拟音频设备)`）→ 能量 VAD → 本地 SenseVoice ONNX（CPU 8 线程）→ `bilibili_free` 翻译 → 修正 pass |
| 引擎模式 | `citty run`（**无界面服务模式**，故意不启动字幕窗，不占屏幕不动鼠标） |
| 监控 | `tools/monitor_longrun.py --minutes 58 --interval 30`：每 30 秒采段数/内存/CPU/离线状态写 CSV |
| 音频注入 | `tools/play_wav.py --device …`，62 分钟按真实速度播进虚拟声卡 |

**为什么不直接播原视频**：本机默认输出设备（Senary Audio）是**死流**，它的 loopback 抓不到任何东西
（录出来 -180 dBFS）。所以固定播到能抓的虚拟设备上。

## 二、结果（57.6 分钟 / 108 次采样）

```
运行         57.6 分钟（采样 108 次，引擎离线采样 0 / 108）
语音段       979 → 992（含监控结束后收尾的十几段）
完成翻译     978 → 992    丢弃 0    报错 1
翻译速率     16.1 段/分钟
内存         408 → 331 MB（**降了 77MB**，无泄漏）
CPU          峰值 7%，均值 4%（16C/24T，ASR 只占 8 线程）
字幕产出     994 条双语，75,489 字符，覆盖 00:00:16 → 01:01:42
```

- **零崩溃、零丢弃、零断线**：108 次采样全部在线。
- **唯一的 1 次报错**出现在第 45 分钟，随后自动继续（同句仍成功翻译），没有累积。
- 内存不涨反降说明 ASR/MT 的临时缓冲都被回收了，**不存在随时间泄漏**。
- CPU 均值 4% 是因为 62 分钟里大部分时间在等音频（说话只占 64%），ASR 本身是毫秒级。
- 免费翻译接口 **994 次请求没有被限速/封禁**（44 分钟内送达 900+ 次）。

## 三、长测暴露的两个真问题

### 问题 1（严重）：9.1% 的句子尾巴带标签碎片

994 条里 **90 条**带着 `>`、`ma` 这类碎片：

| 实际输出 | 应然 |
|---|---|
| `I keep refreshing my email like a crazy personperio>.` | `…person.` |
| `They said we'd hear back by this weekma So I'm… patient>.` | `…this week. So I'm… patient.` |
| `$50 dollarsma max.` | `$50 max.` |
| `I know every time my phone buzzes, I think it's the<>.` | `…it's the.` |

**定位过程**（每一步都留了证据）：

1. 先怀疑文本清洗不够 → 离线把 WAV 按同样的 VAD 重切 992 段全部转写，**一个残渣都没有**。
2. 那就不是离线链路的问题 → 实时重放那 24 秒：`CITTY_DEBUG_RAW_ASR=1` 打出**模型原始输出**，
   确认 `weekma` / `patient>` 是模型直接吐出来的，不是清洗漏了。
3. 查词表：`<`(9702) `>`(9704) `|`(9714) 是**独立 token**，模型在段落边界松动时会把
   `<|withitn|>` 一类标签**拆成碎片**吐出来（`patient` + `>`）。
4. 对比"采集到的音频"和"源文件"：**同一台机器、同一段内容，读文件转写干净，抓 loopback 转写
   就出碎片**，而且 soundcard 明确警告 `data discontinuity in recording`（WASAPI 丢块，
   接缝处音频被硬拼）。**碎片与采集丢块相关**。
5. 顺带发现：源文件在某些段落边界**也会**吐出前置碎片（`you veryI'm a very patient person.`），
   所以这是"边界效应 + 采集丢块放大"，不是单纯的采集 bug。

**已修的部分**：`citty/asr.py::clean_sense_voice_text()` —— 清完整标签、清裸的 `< > |`、
压掉标点前多空格、压掉重复逗号。语料全部来自长测真实输出，单测在
`apps/engine/tests_asr_clean.py`（14 条用例，14/14 通过）。

修复验证（两个层面，都留了产物）：

| 验证 | 结果 |
|---|---|
| 拿长测产出的 **994 条真实句子**离线过一遍新清洗函数 | 带残渣 **90 → 0（9.1% → 0.0%）**，只改动了那 90 句，其余 904 句一字未动 |
| **实时链路**集成验证：重放同一段 176 秒音频 | 41 条字幕，**带 `< > \|` 的 0 条**（产物 `out/longrun_fixed.srt`） |
| 改完引擎重跑 `.\test-p1.ps1 -SkipLive` | **P1 ACCEPTANCE: PASS**（无回归） |
| 单测 `apps/engine/tests_asr_clean.py` | **14/14**（含"不能误伤"用例：省略号 `...`、`drama`、`trauma`、纯中文句） |

> 注意：修复**这一次**的实时重放里 `ma` 类残余恰好是 0 条，但**同一段音频在前一次重放里出现过**
> `They said we'd hear back by this week,ma So I'm trying to be patient.` ——
> 说明这类残余是**间歇性**的（跟采集丢块的时机有关），**不要**因为一次干净就认为它没了。

**没修的部分（诚实交代）**：`weekma` 里的 `ma`、`personperio` 里的 `perio` 是模型拼错的
**词内碎片**，字符串层面**没法安全去掉** —— `drama` 去掉 `ma` 就废了，加白名单规则会误伤正文。
真正的解法在采集链路（减少丢块），已在 `citty/audio.py` 里做了两件事：

- **短读补齐**：原来 `rec.record()` 的返回长度从不校验，少给样点就等于音频时钟偷偷变快、
  字幕时间轴一路漂。现在短读会补齐到整块并计数。
- **丢块可计数**：把 soundcard 的 `data discontinuity` 警告接成计数器，采集线程每 30 秒
  在日志里报一次（`采集诊断: 运行 N 块, 音频不连续 X 次, 短读 Y 次`）。原来这个警告在日志里
  一闪而过，没人知道它的频率 —— 现在它是**可量化的指标**。

> 下一步（P2 之前）：把采集丢块率压下去（换 48k 采集后自己重采样、加大 blocksize），
> 再跑一次长测看 `weekma` 类残渣是否跟着下降。**在那之前不要声称这类残渣已解决。**

### 问题 2（中等）：素材本身有 23% 中文，白跑了 zh→zh 翻译

视频是"英文对话 + 中文讲解"的教学片，`English` 行里混中文的句子占 **227/994 (22.8%)**。
这些句子的源语言是中文、目标语言也是中文，翻译接口把它们**改写**了：

| 原文（ASR） | 翻译后（zh→zh） | 问题 |
|---|---|---|
| `好哦。` | `好的。` | 被改写 |
| `所以我在努力保持耐心。` | `所以我正在努力保持耐心。` | 被改写 |

**后果**：白花 22.8% 的翻译请求，还引入了"原文本来是对的、翻译后被改错"的风险。
**解法**：SenseVoice 的原始输出里带语言标签（`<|zh|>`/`<|en|>`），可以在清洗时**解析出来**
写进 `ASRResult.lang`，然后会话层判断 `src_lang == tgt_lang` 就**跳过翻译、直接透传**。
本次没有实现（属于 P3 多语种路由的天然一部分），已记录为待办。

## 五、复现方法

```powershell
# 1) 抓素材（任意 B 站视频/关键词，自动挑最长的）
python tools\fetch_audio.py --search "英文播客 podcast" --min-minutes 45
python tools\check_audio.py out\samples\xxx.wav          # 体检：音量/静音/抽查转写

# 2) 无界面起引擎（不占屏幕）
cd apps\engine
python -m citty.cli -c D:\Citty\config.local.yaml run

# 3) 另开一个窗口：把素材喂进虚拟声卡（真实速度播放）
python tools\play_wav.py out\samples\xxx.wav --device "扬声器 (网易虚拟音频设备)"

# 4) 后台监控 + 收尾出总结
python tools\monitor_longrun.py --minutes 58 --interval 30
python tools\analyze_srt.py out\longrun.srt              # 质量体检
```

复现这条链路踩过的坑，见 [14-P1验收与测试.md](14-P1验收与测试.md) 的排障表。
