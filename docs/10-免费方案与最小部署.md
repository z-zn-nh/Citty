# 免费资源与"最少部署"方案：每个阶段到底要多大的机器

> 2026-10-06。**最少部署 = 能白拿的都白拿，能不装的都不装。**
> 本文里标 ✅ 的是**本机实测过**的，标 ⚠️ 的是**没能联网核实**（这台机器出不了国，github.com 实测超时），额度类数字一律"以官网为准"。
> 相关：[08-远端服务器部署方案](08-远端服务器部署方案.md)、[09-VPS规格汇总](09-VPS规格汇总.md)。

## 0. 一句话结论

> **按最少部署原则，四个阶段全上的 VPS 需求是 0。**
>
> P1 字幕、P3 路由、P4 多语种**全部用免费 API**，P2 配音也有**零 key、零权重、零显存**的免费方案（edge-tts）。
> 只有当你想要**离线 / 隐私 / 不被免费额度限制 / 实时接管原声**时，才需要租机器——
> 这时候按 [09](09-VPS规格汇总.md) 买 **24GB 显存那一档**就够四阶段全功能。

## 2. 每个阶段的"最少部署"方案

### P1 · 实时字幕 —— VPS 需求 **0**，本地模型 **0 个**

```
本机：WASAPI loopback 采集 → 能量法切句 → [免费额度 ASR] → [哔哩哔哩免费翻译] → 字幕窗
       系统自带              纯 numpy 无模型     唯一需要 key 的地方    免费且无需 key      系统自带
```

**P1 每个环节到底要装什么**（已按代码核实 ✅）：

| 环节 | 谁在做 | 要不要 key | 要不要装模型 |
|---|---|---|---|
| 音频采集 | Windows WASAPI loopback（SoundCard） | 不要 | **不要**（系统能力） |
| 切句 / VAD | `segmenter.py` 的 **RMS 能量法**（`rms_db()`，纯 numpy） | 不要 | **不要**（无模型） |
| 标点 | 云端 ASR 自带（`use_itn` / 云端模型直接出标点） | 不要 | **不要** |
| **ASR** | 云端 `openai_compat`（默认硅基流动） | **要一个免费 key** | **不要** |
| **翻译** | **哔哩哔哩免费接口**（`mt.backend: bilibili_free`） | **不要** | **不要** |
| 字幕显示 | Tk 置顶窗 / 浏览器 overlay（可当 OBS 浏览器源） | 不要 | **不要** |

> 核实结论：引擎本体 **15 个 py 文件 / 85KB**，`grep 'import torch|onnxruntime|funasr|transformers|whisper|modelscope'` 结果为空 —— **引擎零模型依赖**。
> 所以 P1 的最小依赖 = **1 个免费 ASR key**；除它之外全是代码和系统能力。

**只有这几种情况才需要本地部署 ASR**（否则别装）：

| 触发条件 | 装什么 | 体积 | 显存 |
|---|---|---|---|
| **拿不到任何免费额度**（百炼要实名/开通、硅基流动余额 0） | **SenseVoice ONNX int8 + sherpa-onnx** | **0.22 GB + 28 MB 运行时** | **0（CPU）** |
| 断网 / 离线，或不想让音频离开本机 | 同上 | 0.22 GB | 0 |
| 想要流式低延迟 | Qwen3-ASR-**0.6B-streaming** | 0.69 GB | 1.5 GB |
| 英文为主、要最稳 | faster-whisper large-v3-turbo | 1.51 GB | 1.6 GB |
| 中文质量优先 | Qwen3-ASR-1.7B | 4.38 GB | 5.0 GB |

> **这一档已经跑通了**（不是设想）：`sherpa-onnx` + SenseVoice int8，CPU 上 5 秒片段 **110ms（RTF 0.022）**、
> 中文样例 **CER 0.0**、英文访谈 5 段 5 译 0 错，**零 key 零显存**。
> 命令与实测数据见 [13-P1本地部署最简方案](13-P1本地部署最简方案.md)。

**如果要一个"永不依赖别人"的离线 P1 兜底**，最小组合是 **两个文件 = 1.61 GB**：
`SenseVoice-GGUF(q8) 0.24 + Hy-MT2-1.8B-Q6_K 1.37`（ASR 与翻译各自的本地方案），**全 CPU、零显存**。
注意：① 屏幕上的字幕来源得自己有（本地 ASR）；② 翻译也可以用**哔哩哔哩免费接口**，那连这 1.37GB 都省了。

- 引擎本身只吃 0.26 Mbps 上行（[08](08-远端服务器部署方案.md) §2 有推导），**你和视频网站之间的网络就够用了**
- 截至现在：**一个模型都没下**（六个缓存目录全部确认不存在）

### P2 · 配音 —— VPS 需求 **0（影子配音）** / 8~16GB（实时接管原声）
```
本机：字幕文本 → edge-tts 合成 → 播放/混流（影子配音）
需要成品时：demucs 分离人声与 BGM → 替换 → 混流（这一步吃 CPU，离线跑）
```
- **影子配音（字幕同步播 TTS 声音）完全不需要 GPU**：edge-tts 实测 RTF 0.15~0.26，比实时快 4~6 倍
- 人声分离（demucs）是唯一要算力的一环，但它是**离线批处理**（一个视频跑一次），CPU 慢一点也能忍
- 要"实时接管原声、音色克隆"才需要 GPU（CosyVoice2 → 16GB 档）

### P3 · 视频类型路由 —— VPS 需求 **0**
```
云端免费视觉/文本模型（GLM-4V-Flash / GLM-4-Flash）→ 判定类型 → 选翻译模型
或：直接写规则（标题/分区/关键词）
```
- 路由是**每个视频判一次**，不是每句判一次 → 免费 API 的限速完全够
- 本地跑 JEV-9B 要 17.2GB 权重（[07](07-本地部署可行性.md) 实测），在免费方案里**完全没必要**

### P4 · 多语种 —— VPS 需求 **0**
- 翻译：哔哩哔哩已覆盖 **150 语种**（免费）
- 配音：edge-tts 覆盖 **100+ 语言**（免费）
- 只有"小语种配音要用特定音色/克隆"时才需要自建 TTS

## 3. 每阶段要多大的 VPS（要自建时才看）

| 阶段 | 零部署方案 | 若这一阶段要自建 | VPS 规格 | 价格量级（**以官网为准**） |
|---|---|---|---|---|
| **P1 字幕** | 免费 ASR 额度 + 哔哩哔哩免费翻译 | ASR 自建（SenseVoice，234M，可 CPU） | **2C4G，无 GPU** | ¥30~60/月 |
| P1 高质量 | — | ASR 1.7B + MT 7B | **GPU 8~16GB** | ¥1~2/小时 |
| **P2 配音（影子/离线）** | edge-tts（免费无 key）+ demucs | demucs 自建（离线批处理） | **4C8G，无 GPU** | ¥60~120/月 |
| P2 配音（实时接管原声） | — | CosyVoice2 / IndexTTS-2.5 | **GPU 16GB** | ¥1.5~2.5/小时 |
| **P3 路由** | GLM-4V-Flash / GLM-4-Flash（免费） | 2B 决策模型（1.22GB） | **2C4G，无 GPU**（或并入 P1 机器） | 与 P1 共用 |
| **P4 多语种** | 哔哩哔哩（150 语种）+ edge-tts（100+ 语） | 不需要 | **0** | 0 |

**汇总**：四阶段全部"最少部署"走法 → **0 台 VPS**。
**P1 单独看**：**0 台 VPS + 0 个本地模型 + 1 个免费 key（ASR）**，翻译连 key 都不用。
要做本地兜底时，最小是两个文件 **1.61 GB**（见 §2）。
要一部机器兜住全部四阶段、又不依赖免费额度 → **24GB 显存 / 16C / 64GB / 200GB**（见 [09](09-VPS规格汇总.md)）。

## 4. 免费方案的真实代价（先说清楚再上）

| 风险 | 说明 | 对策 |
|---|---|---|
| 额度会变 | 免费额度、免费模型清单、每日限速都可能随时调整 | 代码里保留多后端（我们本来就是适配器架构），换一行配置就能切 |
| 免费 API 没有 SLA | 高峰期会慢、会 429 | 引擎里补**降级链**：主后端失败 → 备用后端 → 本地 mock |
| **edge-tts 是非公开接口** | 它是 Edge 浏览器"朗读"服务的非公开 API，可能被限流/变更；**不支持音色克隆** | 要稳定/要克隆就自建 CosyVoice2（GPU）；日常影子配音够用 |
| 音频会离开本机 | edge-tts 送到微软，云 ASR/MT 送到平台 | 隐私敏感内容走本地部署（[07](07-本地部署可行性.md)） |
| 合规 | AI 合成语音有标识要求；第三方 TTS 的使用条款要自己过一遍 | 见 [04-路线图与风险](04-路线图与风险.md) 的合规清单 |

| en-US-AriaNeural | The neural network was trained on…（78 字） | **1087 ms** | **5.19 s** | **0.21** | `out/tts_demo_en.mp3`（31KB） |

**哔哩哔哩免费翻译**：en→zh 801ms / zh→en 574ms（上一轮实测，无需 key）。
**免费额度现状**：硅基流动 402（余额 0）、百炼 403（服务未开通）——两家都是"key 有效、额度要自己去领/开通"。

## 6. 建议的推进顺序

| 步 | 做什么 | 成本 | 部署量 |
|---|---|---|---|
| 1 | 本机把引擎跑起来：ASR 用**任一免费额度**，MT 用哔哩哔哩（默认已是） | 0 | 0 |
| 2 | 顺手注册**智谱**（拿 GLM-4V-Flash 免费额度），P3 路由就有了 | 0 | 0 |
| 3 | P2：用已经接好的 `citty say` 做影子配音；要成品时本地跑一次 demucs | 0 | 0（demucs 是 pip 包，权重 ~0.16GB） |
| 4 | 只有当"免费额度不够/要离线/要实时接管原声"时，才按 [09](09-VPS规格汇总.md) 租 **24GB** 那一档 | ¥2/小时量级 | 一台 |

**一句话**：现在这个阶段，**别买机器**。先把免费资源和 `citty say` 用起来，等真被额度卡住了再租。
